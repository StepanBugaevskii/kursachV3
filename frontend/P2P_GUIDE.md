# P2P File Sharing Guide

## Как это работает

MeshShare использует WebRTC для прямой передачи файлов между пирами (P2P), без загрузки на центральный сервер.

### Архитектура

1. **WebSocket Signaling** - Backend (socket.io) координирует подключения между пирами
2. **WebRTC Data Channels** - Прямая передача данных между браузерами
3. **Chunk-based Transfer** - Файлы разбиваются на чанки по 1MB для эффективной передачи
4. **IndexedDB Storage** - Локальное хранение чанков для раздачи другим пирам

### Процесс загрузки файла

1. Файл разбивается на чанки по 1MB
2. Чанки сохраняются в IndexedDB браузера
3. Метаданные чанков отправляются на backend
4. Пир регистрируется как провайдер этих чанков
5. Другие пиры могут запросить чанки напрямую через WebRTC

### Процесс скачивания файла

1. Получить список провайдеров чанков с backend
2. Подключиться к пирам через WebRTC
3. Запросить чанки напрямую у пиров
4. Собрать чанки в файл
5. Сохранить чанки локально для раздачи другим

## Использование

### 1. Автоматическая инициализация

P2P клиент автоматически инициализируется при входе пользователя.

### 2. Загрузка файла

Просто загрузите файл через UI - он автоматически станет доступен для P2P раздачи.

### 3. Подключение к пирам

На странице `/peers` вы можете:
- Видеть всех онлайн пиров
- Кликнуть на пира для подключения
- Или ввести Peer ID вручную в P2P Status карточке

### 4. Скачивание файлов

При скачивании файла система автоматически:
- Ищет пиров с нужными чанками
- Подключается к ним через WebRTC
- Скачивает чанки напрямую (P2P)
- Fallback на HTTP API если пиры недоступны

## Технические детали

### WebRTC Configuration

```typescript
iceServers: [
  { urls: 'stun:stun.l.google.com:19302' },
  { urls: 'stun:stun1.l.google.com:19302' },
]
```

### Data Channel Protocol

Сообщения в data channel имеют формат:
- Byte 0: Message type (1 = chunk data)
- Byte 1: File ID length
- Bytes 2-N: File ID (UTF-8)
- Bytes N+1 to N+4: Chunk index (uint32)
- Bytes N+5+: Chunk data

### Chunk Request Flow

1. Peer A отправляет `chunk:request` через WebSocket signaling
2. Backend пересылает запрос Peer B
3. Peer B читает чанк из IndexedDB
4. Peer B отправляет чанк через WebRTC data channel
5. Peer A получает чанк и сохраняет локально

## Troubleshooting

### P2P не инициализируется
- Проверьте, что пользователь залогинен
- Проверьте подключение к backend WebSocket
- Откройте консоль браузера для логов

### Не удаётся подключиться к пиру
- Убедитесь, что пир онлайн
- Проверьте, что оба пира за NAT с поддержкой STUN
- Для сложных NAT может потребоваться TURN сервер

### Скачивание через HTTP вместо P2P
- Это нормальный fallback если пиры недоступны
- Проверьте, что у пира есть нужные чанки
- Проверьте WebRTC соединение в консоли
